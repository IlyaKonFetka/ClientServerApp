# ClientServerApp

Тестовое задание на позицию Android-разработчика: два Android-приложения, которые общаются по WebSocket, и общий модуль с моделями.

## Что делает

**Server** работает на смартфоне с root-доступом:

- периодически сканирует приватную директорию другого приложения (в примере это `/data/data/com.android.chrome`) и строит дерево файлов;
- хранит историю сканов в SQLite и показывает изменения между сканами (добавленные и удалённые файлы подсвечиваются);
- архивирует директорию и умеет восстановить её из архива: останавливает приложение, подменяет данные, выставляет права и перезапускает его;
- поднимает WebSocket-сервер на Ktor (Netty) и выполняет команды клиентов.

**Client** подключается к серверу по сети и управляет им удалённо: запуск и остановка сканирования с заданным интервалом, просмотр последнего скана и дерева файлов, перезапись директории.

**common_code** — общие модели и адаптеры сериализации, которые используют оба приложения.

## Протокол

Текстовые команды поверх WebSocket: `START_SCAN:<interval>`, `STOP_SCAN`, `GET_LAST_SCAN`, `GET_META-INF_AND_TREE:<id>`, `OVERWRITE:<...>`, `GET LIST`. Ответы передаются в JSON (Gson).

## Стек

Kotlin · Ktor Server / Client · WebSockets · Coroutines · Jetpack Compose · SQLite · Gson · многомодульный Gradle-проект

## Модули

```
server/       — серверное приложение (root)
client/       — клиентское приложение
common_code/  — общие модели и адаптеры
```
